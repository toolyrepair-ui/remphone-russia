# REMPHONE — брендовая дизайн-система

Версия: **2026-08-22**
Статус: актуальный источник визуальных решений
Кодовый источник токенов: `styles.css`

## 1. Направление

**Точная техническая помощь.**

REMPHONE должен выглядеть как прямой, современный и понятный сервис ремонта, а не агрегатор, каталог мастерских или типовой SaaS.

Характер:

- надёжный;
- предметный;
- спокойный;
- технический, но понятный;
- без декоративной «технологичности» ради эффекта.

Единственная визуальная подпись — тонкая диагностическая линия или рамка, отмечающая реальную зону ремонта на фотографии телефона. Не повторять её на каждом элементе.

## 2. Палитра

|---|---|---|
| Основной тёмный | `--brand-navy` | `#0B1F3A` |

| Главный CTA | `--brand-red` | `#D80C32` |
| CTA hover | `--brand-red-dark` | `#B90829` |
| Красный логотипа | `--brand-red-logo` | `#FF153C` |
| Основной текст | `--text` | `#101828` |
| Вторичный текст | `--text-light` | `#667085` |
| Основной фон | `--surface` | `#FFFFFF` |
| Приглушённый фон | `--surface-muted` | `#F5F7FA` |
| Граница | `--border` | `#DDE3EA` |

| Предупреждение | `--warning` | `#9A6700` |
| Ошибка | `--error` | `#B42318` |

Правила:

- красный — один главный акцент в экранной зоне;
- navy — доверие, структура, тёмные секции;
- красный логотипа не использовать для мелкого текста;
- статусные цвета не заменять фирменным красным;
- не добавлять индиго, фиолетовые SaaS-градиенты и «дофаминовые» цвета.

## 3. Типографика

- Заголовки: `Space Grotesk`, 600/700.
- Основной текст и интерфейс: `Inter`, 400/500/600.
- H1: 48–56 px desktop, 34–40 px mobile.
- H2: 34–40 px desktop, 28–32 px mobile.
- Основной текст: 16–18 px, line-height 1.55–1.7.
- Комментарии и подписи: не меньше 14 px.
- Строка текста: ориентир 60–75 символов.

Заголовок сообщает пользу. Не использовать растяжение букв, искажения и анимации, мешающие чтению или SEO.

## 4. Геометрия

- Контейнер: до 1200 px.
- Текстовый контейнер: 760–820 px.
- Шаг отступов: 4, 8, 12, 16, 24, 32, 48, 64, 96 px.
- Контролы: радиус 8 px.
- Карточки: радиус 12 px.
- Крупные панели: 20–24 px только при необходимости.
- Одна спокойная базовая тень; hover — небольшой подъём до 3 px.

Не оборачивать каждый фрагмент текста в одинаковую большую карточку.

## 5. Действия

### Primary

- красный фон;
- белый текст;
- высота не меньше 48 px;
- одно главное действие на экранную зону;
- конкретный результат: «Уточнить стоимость», «Описать поломку».

### Secondary

- белый фон;
- navy-текст и граница;
- не конкурирует с primary.

### Text link

- для второстепенной навигации;
- понятный текст без «Подробнее», если можно назвать назначение.

Одинаковое действие называется одинаково на всём пути.

## 6. Формы

- Связанный `<label>` у каждого поля.
- Телефон — `type="tel"`, `inputmode="tel"`, `autocomplete="tel"`.
- Необязательные детали раскрываются по запросу.
- Ошибка располагается рядом с причиной, получает `role="alert"` и фокус.
- Во время отправки кнопка показывает состояние процесса и блокирует повтор.
- Успех подтверждает только принятую relay-заявку.
- Touch target — комфортные 44 × 44 px.

## 7. Изображения

Предпочтение:

1. реальные фотографии ремонта;
2. макросъёмка дисплея, платы, разъёма и инструментов;
3. руки мастера в процессе;
4. честные пары «до / после» одного устройства.

Запрещено:

- чужие фасады и мастерские;
- стоковые люди как «наша команда»;
- AI-люди как клиенты или мастера;
- выдуманные адреса, рейтинги и подписи;
- персональные данные на экранах устройств.

AI-графика допустима только как явно декоративная иллюстрация, не как доказательство работы.

## 8. Движение

Допустимо:

- состояние выбранной марки / поломки;
- переход между шагами;
- появление sticky CTA после первого экрана;
- progress / success / error;
- движение 3D-модели в ответ на выбор симптома.

Запрещено:

- бесконечное декоративное движение;
- параллакс на основной воронке;
- анимация layout-свойств вместо `transform` / `opacity`;
- анимации без варианта `prefers-reduced-motion`.

Один срежиссированный момент лучше множества несвязанных эффектов.

## 9. Компоненты

Повторно используемые компоненты:

- header / mobile menu;
- footer;
- mobile contact bar;
- primary / secondary / text CTA;
- карточка бренда;
- карточка поломки;
- карточка услуги;
- progress шага;
- summary выбранного ремонта;
- поле формы, ошибка и success-state;
- FAQ accordion;
- trust fact;
- реальный repair case.

Новые варианты добавлять только при повторном использовании минимум в двух местах.

## 10. Внешние материалы

Сайт, OG-изображение, Яндекс Бизнес и будущие публикации используют:

- ту же палитру;
- те же шрифтовые роли;
- тот же прямой оффер;
- реальные фотографии;
- один красный акцент;
- логотип из `assets/brand/`.

На фото Яндекс Бизнеса не писать телефон, адрес, QR, «скидка» и «лучшая цена».

## 11. Не использовать

- лексику агрегатора;
- брутализм и сломанные сетки;
- glassmorphism в формах;
- custom cursor;
- полноэкранный параллакс;
- глобальный горизонтальный скролл;
- AR без продуктовой задачи;
- глобальную тёмную тему ради тренда;
- ретро / пиксельную стилизацию;
- массовые animated headings.

## 12. Проверка нового UI

Перед публикацией:

1. Сверить с токенами `styles.css`.
2. Проверить 320, 375, 390, 412 px.
3. Проверить клавиатуру и видимый focus.
4. Проверить контраст WCAG AA.
5. Проверить 200% zoom.
6. Проверить `prefers-reduced-motion`.
7. Убедиться, что sticky UI не перекрывает фокус.
8. Сделать скриншоты mobile и desktop.
9. Проверить, что дизайн не добавил новый CTA, обещание или цену.
